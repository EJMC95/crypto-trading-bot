## 1. hl-perps-rsi — fix the structural loss (biggest lever)
`hyperliquid_perps_bot.py`

Re-validation showed this bot as the worst structural loser (−93%/coin): pure
mean-reversion with **no stop and no trend filter**, so it longed falling knives
and shorted bull rallies, then held. The 45/55 threshold relaxation had 6×'d the
trade count and made it worse (fee bleed).

- **Trend filter (new):** only long an oversold dip while price is **above** the
  50-period EMA; only short an overbought rip while **below** it. Trade with the
  tide, never against it.
- **Per-trade stop-loss (new):** 3% adverse move closes the position. Previously
  the only protection was a 5% *daily account* limit, so one position could ride
  all the way down.
- **Thresholds reverted** 45/55 → **30/70** (backtest: strictly better; the chop
  window flips from −56.6% back toward the +9.4% the tighter gate produced).
- **Re-entry cooldown (new):** 4h per coin, to stop churning the same coin every
  loop.
- Verified by unit test: trend filter blocks counter-trend entries; stop-loss
  fires at −3% and realizes the loss; EMA direction correct.

## 2. intraday-daytrader-5m (V5) — churn-reduction patch
`user_data/strategies/DayTraderV5Gated.py` (the deployed copy)

Kept running per your call, but throttled. The live losses were fee-bleed from
re-buying into the same chop, not a directional blowup.

- **Entry now fires on a fresh momentum cross** (`crossed_above` on RSI, and on
  close-vs-fast-EMA) instead of a sustained level that was true on every candle —
  ~one entry per impulse.
- **CooldownPeriod 3 → 12 candles** (~1h); **StoplossGuard trips one stop sooner**
  (trade_limit 3 → 2). Daily regime gate, ROI ladder, and ATR stops untouched.

> ⚠️ Honest caveat: re-validation found the 5m-scalp approach is negative-edge at
> scale regardless of parameters (−38.6%, 9% win, PF 0.08). This patch reduces the
> bleed; it does **not** manufacture an edge. Watch trade frequency + win rate for
> a week before trusting it, and keep V4/V6 as the core earners. Easy to revert.
> (The dead root copy `strategies/DayTraderV5Gated.py` was left untouched — only
> `user_data/` ships in `Dockerfile.freqtrade`.)

## 3. listing-sniper — stop the P&L resetting to $0 on redeploy
`listing_sniper.py`, `bot_pnl_store.py`

The bot recomputed cumulative P&L each loop from the local `sniper_trades.csv`,
which is wiped on a Railway redeploy — that's why it jumped −$300 / 6 closed →
$0 / 0 on 2026-06-25 (a state wipe, not a recovery).

- New durable `paper_trades` table in Postgres + `publish_paper_trade()` /
  `fetch_paper_aggregate()` (guarded; no-op without `DATABASE_URL`, never raises).
- Each closed fill is mirrored into the ledger; the snapshot reconciles CSV with
  the ledger and takes whichever has more closed trades, so totals can only move
  forward — never silently reset.

## 4. Dashboard heartbeat — per-bot freshness in `/pnl.json`
`pnl_dashboard.py`

The daily report had to hand-compute that ikbr-stock-bot was ~85 min behind the
fleet. Now the feed says so directly.

- Each bot in `/pnl.json` now carries `age_sec` and a threshold-aware `stale`
  flag (stock bots get the longer 26h window; crypto bots 180s).
- `meta` adds `n_stale`, `n_live`, `stock_stale_threshold_sec`; `feed_stale` is
  now threshold-aware, so one lagging stock bot no longer trips a false
  whole-feed alarm while a truly frozen feed still does.
