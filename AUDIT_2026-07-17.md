## 1. THE BREAKTHROUGH

**The fleet was making real-money decisions on numbers nobody had measured, and
today it found the number.**

Lighter quotes funding as a fraction **per 8 hours**. Every Lighter consumer in
the fleet annualised it as **hourly** (`rate * 24 * 365`). So every APR the
fleet computed, printed, gated on, logged and stored was **exactly 8x TRUE** —
verified against the venue's own settled series (`/api/v1/fundings`): ETH
predicted `9.6e-05` → published **84.1%**, settled **10.51%**, ratio **8.00**.
The arithmetic closes to the digit: `9.6e-05 * 3 * 365 * 100 = 10.512`.

That is not a labelling error. It is load-bearing:

| Where the 8x landed | Consequence |
|---|---|
| 💸 Funding Farmer's `FUNDING_ENTER_APR=0.40` | The **LIVE** gate meant **~5% TRUE**. It admitted **130 of 214 books — 61% of the venue** — for a rule built to harvest *extreme* carry. It has run on that bar for as long as it has existed, on a threshold **no backtest ever supported**. |
| ⚖️ Counterweight | Its **entire reported profit was the artifact**. Corrected: +$0.858 → **−$0.04**. The book receives carry on both legs, so the bug flattered exactly the quantity it exists to harvest — on a go-live candidate whose shadow record *is* the go-live evidence. |
| 🎫 Ticket Taker's divergence lens | The **only lens with forward edge** — the one tonight's go-live rests on — had its grade inflated by 8x carry credit. Closes read +4.48/+5.12/+4.50% against a +4% TP bar; the excess above the bar **was** the artifact. |
| Family books (long-only) | They **pay** carry, so the same bug made them look **worse** than real. Opposite sign, one cause. |

And it reached the **daily-loss rail** in two books via `account_value()`, so it
was never cosmetic.

### How it was found, and why that's the actual breakthrough

Not by reading code. It fell out of an adversarial **"does this close the gap?"**
lens run against a routine scout change. The change was structurally fine and
would have shipped a 60-day tape of confidently wrong numbers.

The generalisable method: **find the load-bearing constant, then ask what
measured it.** Applied across the day, it withdrew four of the fleet's own
confident verdicts — every one an artifact of an unmeasured number:

1. **"The Funding Farmer is DEAD"** — WITHDRAWN. The `5bps/side` slippage that
   produced "no gate has an edge" was **assumed**. Driving slip to zero isolates
   a **+6.18 bps/trade gross edge over 1,911 trades, both halves positive**. The
   bot is **friction-bound, not edgeless** — and the defect is the **HARD_STOP**
   (0.10 → 0.03 turns 150d from −$15.85 to **+$21.32**), not the gate everyone
   was arguing about.
2. **Counterweight's +13.6%** — it is a **FLOOR, not an estimate**, for the same
   reason: it holds the HL lab's assumed 5bps so exactly one variable changes.
3. **Stock Leaders' "funding adverse selection"** — REFUTED (Spearman −0.174,
   p=0.40). Funding was never its problem.
4. **The implementation-shortfall organ** — it was comparing the live arm's
   *average* entry against the shadow arm's *average* entry over a 7-day window.
   That measures **price drift, not execution**. It reported HYPE entry_slip
   −363.2bps beside exit +359.3bps and still called itself "clean". Withdrawn.

**The lesson cuts both ways, and that is why it matters: an assumed friction can
fake an edge as easily as it can hide one.**

### The doctrine it produced

> **BACKTEST ON LIGHTER ONLY — the venue we trade is the venue we measure.**

Measured today: **every funding backtest in this repo loads Hyperliquid**, and
the Tide Rider set loads HL **+ Binance**. **Both live bots' go-live

The cost is stated honestly rather than hidden: **Lighter's tape is ~438 days**,

real loss of window and it is the price of measuring the venue that holds the
money. **A 438d Lighter result is evidence; a 2.7yr HL result about a Lighter bot
is an assumption wearing a number.**

**`(o)` — the disarm re-armed Tide Rider.** The operator set
`REAL_MONEY_KILL=DISARMED_I_UNDERSTAND` on `tide-rider-lighter-live` to take the
taker live. That service was built from `Dockerfile.trendlighter` — **the taker's
code was not in that image**, so `TT_VENUE` there was inert. The kill switch was
the only thing holding Tide Rider down. Disarming it **booted the bot being
retired** and it re-bought the exact position the operator had just flattened by
hand: `OPEN TRX long $12` at 17:42 Sydney on a $34.67 real book.

**The cause was the instruction, not the operator.** It led with the env vars and
buried the image change in prose — for a service whose image bakes a *different*
bot's CMD, the env is inert and **the disarm is the only thing that lands**: the
most dangerous possible subset of a config change to apply first.

> **A go-live instruction must name the IMAGE before the env, because the image
> decides which bot the kill switch is protecting.** Image → verify → flatten →
> env → **disarm LAST**.

`GO_LIVE_LIGHTER.md` now opens with that as a 🛑 block and inserts a mandatory
verify-the-running-container step. The marker matters: **the ARMED refusal is
emitted by both bots** — only the wrapper line distinguishes them, which is
exactly what let the disarm hit the wrong one.

**`(m)` — the shadow arm crash-looped for an hour behind an "online" row.**
`Dockerfile.freqtrade` had never installed `lighter-sdk`, so from 05:35 UTC the
taker died every 5 minutes. Two prior commits reported "shadow arm healthy
(1013.99, 18 closes)" — **both were reading the last publish of the old image**.
A row keeps its last-good values when the writer dies.

> **A stale row is not a heartbeat, and `online` is not a health check.**

This is CLAUDE.md's own rule failing in the exact way it was written to prevent.
The guard missed it because **`lighter` is a pip dependency, invisible to a
guard that models repo-local imports** — it verified the FILE, not the WHEEL.
Same class, one layer down, and it is now **five in four days**. The follow-up
