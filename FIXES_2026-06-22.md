# Fixes — 2026-06-22

Addresses the five issues raised in the weekly review. All trading is dry-run/paper.
Every change is syntax-checked; the paper broker, dashboard totals, and prune
script are unit-tested. Nothing here has been committed or deployed — see
**To deploy** at the bottom.

## 1. Dashboard P&L total no longer inflated by the arb scanner
`pnl_dashboard.py`

The scanners (`cross-exchange-arb`, `triangular-arb`) publish an *optimistic*
paper-arb balance (observed spreads, no slippage) into `pnl_abs`. It was being
summed into one "Total P&L", so the headline read +$143 when the trading bots
were actually −$7.

- Header now shows **Trading P&L** (freqtrade bots only) and **Scanner paper**
  (arb scanners) as separate figures.
- Scanner cards relabel their number "Paper (arb)" instead of "P&L".
- `/pnl.json` now tags each bot `"kind": "trading" | "scanner"` so the weekly
  report can keep them separate too.
- Verified: with live data, Trading P&L = −7.13, Scanner paper = 150.25.

## 2. Legacy pre-rename rows hidden + prunable
`pnl_dashboard.py`, `cleanup_legacy_bots.py` (new)

Old names (`perps-bot`, `momo-bot`, `v4core`, `v5gated`, `v6swing`, `v7momo`,
`v8momo`) linger in the `bot_pnl` table because it's keyed by name and nothing
deletes old keys.

- The dashboard now filters to a `CURRENT_BOTS` allow-list, so legacy rows can
  never reach the grid, the totals, or `/pnl.json` — regardless of the DB state.
- `cleanup_legacy_bots.py` removes them at the source. Dry-run by default;
  `--apply` to commit. Safe no-op without `DATABASE_URL`.

## 3. Scanners self-identify as scanners
`cross_exchange_arb.py`, `triangular_arb.py`

Both now publish `extra={"kind": "scanner", ...}` so their optimistic paper P&L
is never mistaken for realized trading P&L by any downstream consumer.

## 4. Idle hl-* bots now actually paper-trade
`paper_broker.py` (new), `hyperliquid_perps_bot.py`, `hyperliquid_momo_bot.py`

Root cause: in dry-run the bots read the **real Hyperliquid testnet** account
value/positions. That wallet is unfunded (`accountValue = 0`), so they could
never book a trade and showed equity 0.0 / 0 trades forever — alive but inert.

- New `PaperBroker`: a self-contained simulated account ($1000 start, 4 bps
  taker fee) that books fills at the live price, marks to market, and reports an
  equity curve — no funded wallet required. Unit-tested (long, short, flip,
  fees, MTM).
- Both bots use it in dry-run for equity, positions, fills, and the published
  P&L. Live-testnet behaviour (`--live`) is unchanged.
- Verified: booking paper trades moves equity and tracks positions.
- Side effect: funding the testnet faucet is no longer needed for dry-run.

## 5. 5m day-trader fee churn
`user_data/strategies/DayTraderV5Gated.py` (the **deployed** copy)

The live bot went 1 win / 26 losses — fee bleed, not a directional blowup. The
entry test fired on *every candle* momentum stayed elevated, so after each
shakeout it bought straight back into the same chop.

- Entry now fires on a **fresh momentum cross** (`crossed_above` on RSI, and on
  close-vs-fast-EMA) instead of a sustained level — ~one entry per impulse.
- `CooldownPeriod` 3 → 12 candles (~1h); `StoplossGuard` trips one stop sooner.
- The regime gate, ROI ladder, and stops are untouched.

> NOTE: this is a churn-reduction change reasoned from the live loss pattern, not
> a backtested edge. Kraken can't serve the daily OHLCV this strategy needs for
> hyperopt, so validate by watching trade frequency + win rate over the next week
> before trusting it. Easy to revert.
>
> Also fixed a repo hazard: `strategies/DayTraderV5Gated.py` and
> `user_data/strategies/DayTraderV5Gated.py` had **diverged** — only the
> `user_data` copy is baked into the freqtrade image (`Dockerfile.freqtrade`
> copies `user_data/`). The root `strategies/` copy is dead; consider deleting it
> to avoid editing the wrong file again.
